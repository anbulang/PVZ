# PVZ 本地对战视觉精修设计

## 目标

本轮目标是把当前游戏画面从“能玩但粗糙”提升到“结构清楚、元素对齐、素材可信”的状态。优化范围以用户当前截图中暴露的问题为准：太阳、铲子、顶部 HUD、右侧僵尸投放区、左侧房子、小车、脑力图标、双发射手、僵尸死亡动画和实体裁剪。

本轮选择的方向是 **现有布局局部精修**。不做大版式重构，不把卡牌栏改成全新的侧边栏，也不改变当前 Canvas 架构。

## 已确认决策

- 视觉优先，规则只做明确小改。
- 同时兼顾 1280x720、1440x900 和全屏窗口，不只修单张截图。
- 保留顶部三段结构：左侧植物卡牌区、中间时间/脑力/压力、右侧僵尸卡牌区。
- 保留左侧房子和小车区域。
- 保留中间 5x9 草坪。
- 保留右侧僵尸投放区。
- 小鬼僵尸脑力值从 60 下调到 40。

## 非目标

本轮不处理以下内容：

- 不取消僵尸自动出现。
- 不重做完整双方对战规则。
- 不大幅重调植物和僵尸战斗数值。
- 不新增单位、地图、联机、关卡或账号系统。
- 不迁移到 Phaser 或其他引擎。
- 不重制整个素材库，只处理当前游戏实际使用且明显有问题的素材。

“植物太强”“整体逻辑偏植物方”“真正双方手动对战”记录为后续玩法平衡专题，不混入本轮视觉精修。

## HUD 与布局设计

### 总体结构

当前画面的大结构保留：

- 左上：植物方资源和工具。
- 顶部左侧：植物卡牌。
- 顶部中间：时间、脑力、压力。
- 顶部右侧：僵尸卡牌。
- 左侧竖向区域：房屋和 5 台小车。
- 中央：5x9 草坪。
- 右侧：僵尸投放区。
- 底部：状态栏。

布局修改只做局部精修，目标是“看起来明显更整齐”，而不是“换成另一个游戏界面”。

### 太阳和铲子

太阳值和铲子要属于同一个“植物工具槽”视觉系统。太阳值保留在左上附近，铲子放入明确的槽位内，尺寸小于卡牌，不再像一个单独悬浮物。

交互规则保持不变：

- 点击太阳计数区域仍可一键收集阳光。
- 点击铲子槽选择铲子。
- 铲子选中态使用和卡牌一致的高亮规则。

验收标准：

- 太阳、铲子、植物卡牌不重叠。
- 铲子不突兀，不遮挡房子、小车或草坪。
- 点击热区和视觉槽位一致。

### 顶部信息栏

时间、脑力、压力三个信息块要统一高度、边框、内边距和数字对齐方式。脑力不再放进过大的独立方框，使用紧凑的资源槽。

脑力图标使用新的生成素材，不再使用当前难看的手绘符号。数字右对齐，图标左对齐，长数字不会压住边框。

验收标准：

- 时间、脑力、压力在 1280x720、1440x900、全屏下都水平对齐。
- 资源数字不压图标，不越界。
- 压力条和标签不挤在一起。

### 卡牌区

植物和僵尸卡牌保留顶部位置，但需要统一卡牌尺寸、图标缩放、费用 chip、冷却遮罩和禁用态。

植物卡牌重点解决：

- 费用不压住植物图。
- 资源不足时不可选择，并有清晰灰罩。
- 选中框贴合卡牌外框。

僵尸卡牌重点解决：

- 缩略图完整显示，不裁掉头、脚或道具。
- 费用 chip 与植物卡牌一致。
- 僵尸选择区更整齐，四列两行对齐。

验收标准：

- 视觉框和点击热区完全一致。
- 卡牌图标完整。
- 冷却、禁用、选中三种状态可区分。

### 僵尸投放区

右侧投放区保留，但要和草坪行对齐。背景和边框需要像草坪右侧的投放通道，而不是一个单独贴上的灰色大框。

投放区的行分隔需要和 5 条泳道中心对齐。投放区内预览僵尸时，僵尸脚底要和对应行中心一致。

验收标准：

- 投放区上下边界不压住顶部 HUD 或底部状态栏。
- 投放区 5 行和草坪 5 行对齐。
- 投放区边框、底色和主画面风格一致。

### 左侧房子和小车

左侧房子重新绘制，但保持当前“房子 + 小车车道”的结构。重点是让房子、车道和草坪自然连接，不像贴图拼接。

小车继续使用当前素材方向，但需要统一每行位置、显示尺寸、裁剪和阴影。小车不能和房子细节互相挤压，也不能被裁掉。

验收标准：

- 房子不怪异、不突兀。
- 5 台小车和 5 行草坪中心对齐。
- 小车完整显示，不被房子遮挡得奇怪。

## 素材与动画设计

### 太阳图标

太阳图标改回更接近原先清晰太阳的风格，但重新处理透明边距，避免缺边和裁剪。太阳拾取物和太阳计数图标可以使用同源素材，但在不同场景下使用不同尺寸。

验收标准：

- 太阳拾取物完整显示。
- 太阳计数图标不会被资源槽裁剪。
- 阳光数值和太阳图标不互相压住。

### 脑力图标

脑力图标重画为更真实的脑子形态，但保持卡通游戏风格。它是资源识别图标，不是主角素材，因此不能过大、过亮或抢走卡牌注意力。

验收标准：

- 一眼能看出是脑力资源。
- 小尺寸下仍可读。
- 不像随手画的符号。

### 双发射手

双发射手重画为豌豆射手变体，不再使用两个炮口。它应该和豌豆射手相近，但通过眼睛形状、表情、叶片或轻微色差区分。

战斗逻辑仍然是双发射，但视觉上只有一个炮口。

验收标准：

- 双发射手不是两个炮。
- 和普通豌豆射手能区分。
- 卡牌和场上显示一致。

### 僵尸死亡动画

僵尸死亡时不能向上飘。死亡动画使用底部中心锚点，动作方向为向前或向下倒地，并逐渐消失。

实现上，死亡效果需要携带明确的地面锚点语义，渲染时不得随着动画进度增加负向 y 偏移。

验收标准：

- 僵尸死亡不向上移动。
- 脚底或倒地点贴近原行地面。
- 普通、小鬼、旗帜、路障、铁门、铁桶、冰车、橄榄球等当前可玩僵尸死亡表现都不回退到旧的程序化形状。

### 僵尸完整显示

统一僵尸 spritesheet 的显示框和缩放策略。卡牌中优先完整展示轮廓，战场中优先保证脚底对齐和头部不裁剪。

验收标准：

- 卡牌里不裁头、不裁脚。
- 战场里不漂浮、不沉到格子下方。
- 大体型僵尸可以缩小，但不能破坏行对齐。

## 规则小改

本轮唯一规则数值改动：

- 小鬼僵尸脑力值从 60 改为 40。

对应测试行为：

- 初始 100 脑力时投放小鬼僵尸后，应剩余 60 脑力。

其他规则保持当前版本不变。

## 响应式要求

本轮不是做移动端适配，但必须覆盖常见桌面窗口：

- 1280x720：主验收尺寸。
- 1440x900：更高窗口下 HUD 和战场不散。
- 全屏：顶部栏、投放区、左侧房子、小车不漂移。

Canvas 内部仍以固定逻辑坐标绘制；窗口缩放由现有页面缩放和截图验证覆盖。设计目标是避免元素在逻辑坐标中本身重叠或裁剪。

## 测试与验证

### 单元测试

需要覆盖：

- 小鬼僵尸成本为 40。
- 阳光不足时不能选择植物。
- 卡牌点击热区和视觉框一致。
- HUD 区块不互相重叠。
- 僵尸死亡效果带有地面锚点，不允许向上运动。
- 关键生成素材存在：太阳、脑力图标、左房子、双发射手、死亡动画。

### 浏览器验证

需要覆盖：

- 1280x720 首屏截图。
- 1440x900 首屏截图。
- 全屏或大窗口截图。
- 选择植物、资源不足、投放僵尸、僵尸死亡、阳光收集。
- 截图人工检查太阳、铲子、脑力、投放区、房子、小车、双发射手和死亡动画。

### 完成前验证

完成前必须运行：

```bash
npm test
git diff --check
node scripts/verify-browser.js http://localhost:5174 tests/browser-actions.json
node scripts/verify-browser.js http://localhost:5174 tests/browser-layout-actions.json
node scripts/verify-browser.js http://localhost:5174 tests/browser-visual-assets-actions.json
```

浏览器验证如果因为本地服务未启动失败，需要先启动游戏服务，再重新执行。不能只凭代码检查声明完成。

## 风险与处理

- 生成素材可能风格不稳定：优先减少帧数、加强底部中心锚点和透明边距，而不是回退到程序化绘制。
- HUD 精修可能影响点击热区：每次改视觉位置都必须同步 `input.js` 的命中区域，并用布局测试验证。
- 多窗口验证可能暴露 Canvas 外壳缩放问题：本轮只解决桌面窗口常见尺寸，不扩展到移动端布局。
- 旧计划文档中已有更大范围的对战规则改造，本轮不执行该范围，以本设计为准。
